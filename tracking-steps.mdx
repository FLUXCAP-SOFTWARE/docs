## Overview

EASYCRED provides distinct tracking mechanisms tailored to whether you are running a **Hosted (`API_HOSTED`)** or **Headless (`API_HEADLESS`)** integration:

| Tracking Method | Integration Mode | Endpoint / Mechanism | Required Headers | Description |
| :--- | :--- | :--- | :--- | :--- |
| **Webhooks** | Hosted & Headless | HTTP POST to your server | `x-webhook-signature`, `x-webhook-timestamp`, `x-webhook-nonce` | **Primary for Hosted.** Real-time push events (`journey.updated`, `journey.completed`, etc.) matching `journeyId`. |
| **List Applications** | Hosted & Headless | `GET /api/v1/partner/leads` | Standard HMAC headers | Paginated audit list of all applications originated by your partner account. |
| **Application Status** | Hosted & Headless | `GET /api/v1/partner/leads/{applicationId}/status` | Standard HMAC headers | Query terminal or processing status using the 24-char hex `applicationId`. |
| **In-Flight State Polling** | Headless Only | `GET /v1/partner/journey/{journeyId}` | Standard HMAC + `X-Journey-Session` | Real-time state machine driver returning lender offers, actions, and current step. |

---

## Tracking ID Architecture

Understanding EASYCRED's tracking IDs ensures seamless reconciliation:

- **`journeyId` (`jrn_<uuid>`):** Returned by `POST /journey/initiate` for both Hosted and Headless channels. It is the primary reference delivered in all **Webhook events** (`data.journeyId`), enabling your system to correlate real-time webhook updates directly with the initial initiation call.
- **`applicationId` (24-character hex MongoDB ObjectId):** Generated when the loan application is recorded in EASYCRED's database. Returned in `GET /api/v1/partner/leads` and queried via `GET /api/v1/partner/leads/{applicationId}/status`.
- **Internal Reference IDs:** Internal banking rail or lender session IDs (such as 36-character UUID strings like `01a18...`) are managed privately by EASYCRED's infrastructure. API partners do not use these IDs; you always track externally using `journeyId` or `applicationId`.

## 1. List Enabled Products

Inspect which loan products are currently enabled for your API key:

```http
GET /api/v1/partner/products
```

**Required Scope:** `products:read`  
**Headers:** Standard HMAC headers (`x-api-key`, `x-timestamp`, `x-nonce`, `x-signature`)

```json
{
  "success": true,
  "data": {
    "products": [
      {
        "code": "ONLINE_PERSONAL",

        "category": "PERSONAL"
```

## 2. List Partner Leads & Applications

Retrieve a paginated list of all applications originated by your account. This endpoint returns operational metadata without exposing customer PII:

```http
GET /api/v1/partner/leads?page=1&limit=20
```

**Required Scope:** `leads:read`  
**Headers:** Standard HMAC headers (`x-api-key`, `x-timestamp`, `x-nonce`, `x-signature`)

### Query Parameters

| Parameter | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `page` | integer | `1` | Page index (1-based). |
| `limit` | integer | `20` | Results per page (maximum `100`). |

### Response Example

```json
{
  "success": true,
  "data": {
    "leads": [
      {
        "applicationId": "667a1b3c4d5e6f7a8b9c0d1e",
        "loanType": "PERSONAL_LOAN",
        "loanAmount": 150000,
        "status": "APPROVED",
        "submittedAt": "2026-10-28T07:15:30.000Z"
      }
    ],
    "total": 1,
    "page": 1,
    "limit": 20
  }
}
```

## 3. Get Application Status

Retrieve the current processing or terminal status of an application by its `applicationId`:

```http
GET /api/v1/partner/leads/{applicationId}/status
```

**Required Scope:** `leads:status:read`  
**Headers:** Standard HMAC headers  
*(Requires only standard HMAC headers — no `X-Journey-Session` token needed. Compatible with both hosted and headless applications).*

### Response Example

```json
{
  "success": true,
  "data": {
    "applicationId": "667a1b3c4d5e6f7a8b9c0d1e",
    "status": "COMPLETED"
  }
}
```

## 4. Webhooks vs. Polling

EASYCRED supports asynchronous webhook delivery for status transitions:

- **Webhooks (Recommended for Hosted):** Receive instant HTTP POST push notifications on all state transitions (`journey.initiated`, `journey.updated`, `journey.completed`, `journey.rejected`, `journey.failed`). Webhook payloads include `data.journeyId` so your backend can update customer status in real-time while they use the hosted screens.
- **In-Flight State Polling (Headless Only):** Poll `GET /v1/partner/journey/{journeyId}` using `X-Journey-Session` to drive intermediate UI screens (render offers, request bank details, handle redirects).

See the [Webhooks Guide](/webhooks) to configure endpoints and signature verification.

## Terminal Status Reference

| Status | Description |
| :--- | :--- |
| `COMPLETED` | Loan successfully sanctioned and disbursed. |
| `REJECTED` | Application did not meet lender credit criteria. |
| `NO_OFFERS_AVAILABLE` | No offers returned for the applicant's profile. |
| `OFFLINE_PROCESSING` | Assigned to an EASYCRED credit officer for physical follow-up. |
| `ABANDONED` | Borrower timed out before completing verification. |
| `EXPIRED` | Application exceeded the 72-hour journey TTL. |
