## Response Envelope

Every response from the EASYCRED Partner API uses a consistent JSON envelope:

<Tabs>
  <Tab title="Success">
    ```json
    {
      "success": true,
      "data": { ... }
    }
    ```
  </Tab>
  <Tab title="Failure">
    ```json
    {
      "success": false,
      "error": "Human-readable error message"
    }
    ```
  </Tab>
  <Tab title="Validation Error">
    ```json
    {
      "success": false,
      "error": "Validation failed",
      "details": [
        { "field": "customer.pan", "message": "Invalid PAN format" },
        { "field": "customer.pinCode", "message": "Must be exactly 6 digits" }
      ]
    }
    ```
  </Tab>
</Tabs>

## HTTP Status Codes

| Code | Meaning | Common Causes |
| :--- | :--- | :--- |
| `200` / `201` | Success / Created | Request processed successfully |
| `400` | Validation Error | Malformed request body or invalid field values |
| `401` | Authentication Failed | Invalid signature, stale timestamp (> ±300s), replayed nonce, or missing journey token |
| `403` | Forbidden | Missing required scope or product not enabled for partner |
| `404` | Not Found | Requested journey or application ID does not exist |
| `409` | State Conflict | Action submitted at the wrong lifecycle step or duplicate in flight |
| `429` | Rate Limit Exceeded | API request threshold exceeded |

## Rate Limits

| Metric | Default Threshold | Response Header |
| :--- | :--- | :--- |
| **Per-Minute Limit** | **120 requests / minute** per API key | `RateLimit-Remaining` |
| **Per-Day Limit** | **20,000 requests / day** per API key | `RateLimit-Remaining-Day` |

*Contact EASYCRED technical support if your integration requires custom throughput quotas.*

## Best Practices for Errors

- **On 429:** Implement exponential backoff with jitter and respect `RateLimit-Remaining` headers.
- **On 409:** Re-query journey state (`GET /journey/{journeyId}`) — the journey state has already advanced.
- **On 5xx:** Retry idempotent requests using exponential backoff.
