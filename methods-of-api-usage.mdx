## Overview

EASYCRED offers two integration modes. Select the mode per application when calling the initiate endpoint using the `channel` parameter.

| Feature | Hosted (`API_HOSTED`) | Headless (`API_HEADLESS`) |
| :--- | :--- | :--- |
| **Response Payload** | `hostedUrl` | `journeySession` token |
| **User Interface** | EASYCRED provides the complete UI | You design and build the borrower UI |
| **Step Handling** | Managed by EASYCRED (offers, KYC, e-NACH, e-Sign) | Driven by your backend over REST |
| **Referral Offers** | Rendered automatically on the hosted screen | Delivered in `data.referralOffers[]` for custom UI rendering |
| **Best For** | Fastest go-live; zero frontend development | Deep native app integration with full UX ownership |

---

## 1. Hosted Mode (`API_HOSTED`)

Start a journey and receive a single-use `hostedUrl`. Direct the customer to the URL in a browser or embed it within a secure WebView:

```http
POST /v1/partner/journey/initiate
```
```json
{
  "channel": "API_HOSTED",
  "productCode": "ONLINE_PERSONAL",
  "mobile": "9876543210",
  "customer": { ... }
}
```

EASYCRED manages the borrower through all intermediate phases: offer selection, KYC verification, mandate registration, e-Sign, and secondary referral offers (like Apollo Finvest).

**Tracking Progress:**
- Poll application status: `GET /api/v1/partner/leads/{applicationId}/status`
- Or receive live webhook updates on status transitions.

---

## 2. Headless Mode (`API_HEADLESS`)

Your backend controls the applicant experience. Starting the journey returns a `journeySession` JWT token:

```http
POST /v1/partner/journey/initiate
```
```json
{
  "channel": "API_HEADLESS",
  "productCode": "ONLINE_PERSONAL",
  "mobile": "9876543210",
  "customer": { ... }
}
```

### Headless Loop Architecture

1. **Poll State:** Call `GET /v1/partner/journey/{journeyId}` with `X-Journey-Session` to inspect `currentNextAction`.
2. **Handle Actions:**
   - **`POLL`:** Wait `pollIntervalSeconds` and read state again.
   - **`COLLECT`:** Present choices to the borrower and post actions (e.g. `SELECT_OFFER`, `SELECT_GOLD_LOAN_BRANCH`, or `SUBMIT_BANK_ACCOUNT`) to `/journey/{journeyId}/action`.
   - **`REDIRECT`:** Open verification URLs (KYC, e-Sign, e-NACH) for the borrower, then call `/redirect-returned` upon return.
   - **`TERMINAL`:** Read `data.outcome` and conclude the journey.
3. **Handle Referral Offers:**
   When secondary lenders (such as Apollo Finvest) provide offers, they appear in `data.referralOffers[]`. Your app renders the offer card and opens the corresponding `redirectUrl`.
